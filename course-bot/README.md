# Telegram-бот курса (без конструктора)

Python 3.10+ / aiogram 3 / SQLite. Все тексты, кнопки, категории, условия и тарифы лежат в `scenario.yaml`. Чтобы поменять сценарий, код трогать не нужно.

## Что умеет

- **Сценарий из экранов и кнопок.** Переходы между экранами, ссылки, кнопки оплаты, картинки.
- **Категории пользователей.** Выдаются при открытии экрана (`on_enter`), по диплинку (`t.me/бот?start=insta`), после оплаты или вручную из админки.
- **Условия.** Кнопку или целый экран можно показывать только нужным категориям (`any` / `all` / `not`), остальных отправлять на другой экран (`else`).
- **Оплата через Prodamus.** Бот формирует ссылку и принимает уведомление об оплате с проверкой подписи. После оплаты выдаёт категории, показывает экран «спасибо» и пишет админам. Повторные уведомления по одному заказу не дублируют выдачу.
- **Рассылки.** Можно отправить всем, по категории или тем, кто ничего не купил. Поддерживается любой тип сообщения: текст, фото, видео, кружок, файл. Перед отправкой бот показывает превью. Скорость около 20 сообщений в секунду. Тех, кто заблокировал бота, он помечает и пропускает.
- **Админка.** `/stats`, `/user`, `/grant`, `/revoke`, `/categories`, `/export` (CSV для Excel), `/reload` (перечитать сценарий без перезапуска, с проверкой ошибок).

## Вопросы, воронка, напоминания

- **Вопросы.** Всё, что человек пишет боту (текст, фото, голосовое), пересылается админам или в группу из `SUPPORT_CHAT_ID`. Человеку бот отвечает `question_reply` из сценария. Чтобы ответить, нажми «Ответить» на пересланном сообщении: ответ уйдёт человеку от имени бота.
- **Воронка.** `/funnel` — сколько уникальных людей дошло до каждого экрана, нажало «перейти к оплате» и оплатило (за 7 дней; `/funnel 30`, `/funnel 0` — всё время). Админы не считаются.
- **Напоминание о брошенной оплате.** В `scenario.yaml` блок `reminder: {after_minutes: 180, screen: reminder}`. Тем, кто открыл ссылку на оплату и не оплатил, бот один раз отправит экран `reminder`. Купившим и заблокировавшим бота не отправляет. Без блока `reminder` напоминания выключены.

## Запуск локально

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN и ADMIN_IDS
python -m bot.main
```

Без Prodamus бот тоже работает, только кнопки оплаты будут отвечать «Оплата пока не настроена».

## Продакшн (VPS)

Установка описана в корневом README репозитория. Коротко:

```bash
bash /opt/bulaavina_bots/install.sh course-bot bot.bulaavina.ru 8080
nano /opt/bulaavina_bots/course-bot/.env   # BOT_TOKEN, ADMIN_IDS
systemctl restart course-bot
```

Проверка вебхука: `https://bot.bulaavina.ru/health` → `ok`.

## Настройка Prodamus

- `PRODAMUS_URL` — адрес вашей формы, например `https://yourshop.payform.ru`.
- `PRODAMUS_SECRET` — секретный ключ из настроек Prodamus.
- Адрес для уведомлений бот передаёт сам в каждой ссылке (`urlNotification` → `PUBLIC_URL/prodamus/webhook`). Если хотите, этот же адрес можно прописать и в настройках Prodamus.
- Перед запуском сделайте одну **тестовую оплату** (в Prodamus есть тестовый режим). В логах должно появиться уведомление, пользователь должен получить экран `paid`, админ — сообщение «💰 Оплата». Если в логе `bad signature`, проверьте секретный ключ.

## Как править сценарий

Формат расписан комментариями прямо в `scenario.yaml`. Порядок такой: правите файл, отправляете боту `/reload`. Если в сценарии есть ошибка (ссылка на несуществующий экран, тариф или категорию), бот покажет её и продолжит работать на старой версии.

Чтобы картинка шла без внешней ссылки: отправьте фото боту от админа, возьмите `file_id` (например, через @RawDataBot) и укажите его в `photo:`.

## Структура

```
bot/
  main.py            запуск: polling + HTTP-сервер для вебхука
  scenario.py        загрузка/валидация сценария, условия, сборка экранов
  handlers_user.py   /start, переходы, кнопки оплаты
  handlers_admin.py  админ-команды и рассылки
  prodamus.py        ссылки на оплату и проверка подписи
  webhook.py         приём уведомлений Prodamus
  db.py              SQLite: пользователи, категории, платежи
scenario.yaml        тексты и логика
```
